# 02｜项目设计思路

## 从使用任务反推设计

不让用户先学建模命令，而是先回答三个问题：这是哪类辅具？需要与什么部件配合？哪一项尺寸不能由草图猜测？界面组织为「输入草图与文字 → 核对参数 → 查看模型与检查结果 → 按结果修改」。同类案例应先提供易复现的示例供评委试用；修改同一个输入后可与原生成结果对照。

| 决策 | 输出给用户 | 取舍 |
| --- | --- | --- |
| 先选或识别辅具类别，再生成 | 参数名随类别变化，始终显示单位 | 限制在三类模板，不承诺生成任意辅具 |
| 区分明确尺寸与建议尺寸 | 用户能看到待确认项并覆盖建议 | 宁可增加一次确认，也不把草图像素当作毫米 |
| 将制造检查与外观预览分开 | 能看到检查项、状态和修正方向 | 预览好看不能替代几何、切片或受力验证 |
| 设计失败演示 | 展示不能生成、检查未通过或未运行的原因 | 不用自动修复或旧模型掩盖本次失败 |

## 三类案例如何展示

- **握笔器：主案例。** 从笔杆通道与握持外轮廓出发，只改一个明确尺寸，展示模型与检查结果如何变化。
- **餐具手柄：配合案例。** 对比不同配合尺寸的合成示例，检查模型是否按确认后的尺寸生成。展示是几何配合推演，不验证防滑或真实握持效果。
- **矫形护具：边界案例。** 用合成尺寸展示开口壳体与壁厚变化；预览之后注明仿真工况和非医疗用途，不用人体数据证明适配或纠正效果。

## 评委体验验收

同一浏览器会话应能在免登录状态下完成「打开示例、生成、预览并获取模型或检查结果」。录制一组正常案例和一组异常案例；若某个检查只能离线复现，网页与视频须分别标明「系统内检查」和「离线验证」，不能把后处理冒充网页实时能力。具体功能状态以最终演示版本为准。
